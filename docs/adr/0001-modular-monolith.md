# ADR-0001：采用模块化单体与适配器边界

## 状态

Accepted

## 背景

工具需要覆盖 140 项在线控制、离线数据、分析、编排和治理能力，但当前维护团队和
部署形态都是单机 Python 工具。把功能继续放入单个 COM 类会造成强耦合；拆成微服务
则会引入无必要的部署、网络和运维复杂度。

## 决策

采用一个 Python distribution 内的模块化单体。在线 COM、离线解析、分析、安全、
编排、报告通过明确模块边界协作；车型、企业系统和安全算法通过 Protocol/插件扩展。

## 后果

### 正面

- 单机安装和调试简单；
- 离线模块不依赖 CANape；
- 模块可以分别测试并在未来独立拆分。

### 负面

- 仍需共同发布版本；
- 模块边界必须通过代码审查保持。

## 备选方案

- 单一巨型 `CANape` 类：拒绝，职责和测试范围不可控；
- 微服务：拒绝，单机工程工具不需要分布式复杂度；
- 每个专业独立复制核心：拒绝，会造成行为和安全规则漂移。
