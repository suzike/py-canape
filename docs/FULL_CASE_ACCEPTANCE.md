# 空调舒适性全链路验收案例

本案例模拟用户投诉“座舱降温响应慢且 HVAC ECU 存在历史 DTC”，用一条可重复执行的
工程链验证 Agent2Canape 的主要能力。危险 ECU 动作在模拟适配器中执行；可选的真实
CANape 工程门禁只读取工程信息和设备列表，不发送诊断、不写标定、不启动测量。

## 执行

纯软件验收：

```powershell
python examples\hvac_comfort_full_case.py
```

叠加真实 CANape 只读门禁：

```powershell
python examples\hvac_comfort_full_case.py `
  --real-canape-project D:\Software\Canape17\Examples\OfflineAnalysis
```

每次运行创建独立时间戳目录，不覆盖既有证据。

## 案例数据与结论

模拟基线将座舱温度从 35 °C 拉低到 22 °C 的时间常数设为 65 秒；候选标定将时间常数
改善为 30 秒。验收要求候选控制 RMSE 明显低于基线，同时无范围、变化率和采样断点问题。

测量清单使用 100 Hz 任务和 5 秒前触发、20 秒后触发窗口，需要约 2500 个 FIFO 样本。
案例配置为 4096；若误配为 256，规划门禁会在接触 CANape 前拒绝执行。

## 证据产物

每次运行生成：

- `full-case-result.json`：全部阶段、输入、输出和结论；
- `full-case-report.html`：可浏览的工程报告；
- `audit.jsonl`：不可变更哈希链；
- `workflow-checkpoint.json`：工作流检查点；
- `asset-manifest.json`：源资产和结果文件 SHA-256；
- `hvac-comfort-evidence.zip`：自带 manifest 的证据包。

自动化测试还会重新计算最终结果文件哈希，并与资产清单比较，防止生成证据包后结果文件
又被修改而造成清单失真。

## 未替代的现场验收

该案例不能替代真实 ECU 的 XCP/UDS/刷写验收。以下能力仍必须在受控台架执行：

- 实际标定 RAM/ROM 写入、掉电保持和回滚；
- 真实 P2/P2*、网关路由、安全访问与 Tester Present 周期；
- DAQ 极限、FIFO 堵塞、总线负载和长时间录制；
- 断电、总线掉线、ECU Reset、错误 Key 和刷写救援。
