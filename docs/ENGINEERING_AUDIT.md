# Agent2Canape 最终工程审查

审查日期：2026-07-30

审查对象：`src/agent2canape`、测试、示例、脚本、构建配置和全部交付文档

审查视角：真实 ECU 标定、在线测量、整车问题排查、AI/MCP 编排、数据闭环和发布维护

## 结论

Agent2Canape 已形成可安装、可测试、可扩展的 CANape 自动化与 ECU 标定软件基线，
但还不能把“140 个注册契约可解析”解释为“140 项均已在真实 ECU 上完成行为验收”。
当前适合作为工程开发基线和企业适配起点；涉及在线写入、诊断、刷写、显式 CNA 加载、
大规模数据性能和企业审批的能力，仍需真实项目与硬件验证。

## 本轮已修复

| 问题 | 风险 | 处理 |
|---|---|---|
| 产品名只改文档会形成多套接口 | 高 | 发行包、命名空间、CLI、MCP、环境变量、插件组和契约编号统一更名 |
| 工作流 `write=True` 只有标记、没有执行门禁 | 严重 | 默认拒绝写步骤，必须显式 `allow_writes=True` 或 `--allow-writes` |
| 整型测量状态无法被 AI 工具序列化 | 高 | 对 COM 整型状态返回稳定结构 |
| JSON Schema 把 `bool` 当成地址或数值 | 高 | 整数和数值参数显式拒绝布尔值 |
| 工作流超时后上下文管理器仍等待线程 | 高 | 超时立即返回并取消尚未开始的任务 |
| 快照恢复可覆盖危险目录 | 严重 | 拒绝根目录、用户目录、同目录和嵌套目录 |
| 标定版本名可用于路径穿越，加载不验哈希 | 严重 | 限制版本名，原子写文件，加载时校验清单 SHA-256 |
| 已经为高电平的响应被误判为新响应 | 高 | 在完整时间轴上识别边沿后再配对触发 |
| 两状态往返振荡漏报 | 中 | 修正振荡窗口边界 |
| 零时刻异常窗口计算错误 | 中 | 不再把 `0.0` 当成缺失值 |
| ZIP 证据包同名文件静默覆盖 | 高 | 检测同名并显式失败 |

工作流超时只能停止等待，Python 线程不能强制终止已经运行的硬件调用。因此 CANape COM
动作仍被标记为 `thread_safe=False`，超时后需要由动作自身实现取消、停止或恢复策略。

## 模块级审查

| 模块 | 当前可用性 | 主要剩余问题 |
|---|---|---|
| `canape.py` | 会话、设备、测量、标定、诊断、网络和刷写 API 已覆盖 | 指定 CNA、在线写入、诊断和刷写缺少多版本实机矩阵 |
| `calibration.py` | 数据集、差异、合并、计划、回滚、DOE 和优化可用 | 缺少 CDFX/DCM 原生交换、并发仓库锁、多目标约束优化和实验持久化 |
| `ai_tools.py` | 结构化工具、参数摘要审批和单次消费可用 | 自然语言规划仍是关键词路由；审批身份不是企业级可信身份 |
| `mcp_server.py` | FastMCP 工具发现和调用可用 | 缺少会话隔离、资源配额、结构化审计导出和长任务进度 |
| `workflow.py` | 重试、检查点、补偿、Dry-run 和写门禁可用 | 已启动线程不可强制取消；缺少步骤级幂等键和分布式执行 |
| `assets.py` | 预检、清单、快照和恢复可用 | 缺少 CANape 许可证、Vector 驱动、硬件通道和 A2L/HEX 一致性深检 |
| `offline.py` | 表格、MDF、BLF、DBC、基础 A2L/ODX 目录可用 | A2L/ODX 为轻量目录解析，不是完整 ASAM 语义解析器 |
| `analysis.py` | 通用质量、时序、状态、控制和对比分析可用 | 缺少不规则采样置信度、事件配对策略、统计显著性和因果证据等级 |
| `safety.py` | 权限、对象/地址白名单和车辆条件可用 | 底层专家 API 可绕过；缺少双人审批、签名策略和安全状态快照 |
| `reporting.py` | 审计链、ZIP、HTML、Word、Excel 和基础 PDF 可用 | PDF 不适合中文企业版式；审计链缺少并发锁、数字签名和可信时间戳 |
| `plugins.py` | 七领域适配器和入口发现可用 | 内置规则仅为示例基线，不能替代车型级信号与阈值包 |
| `capabilities.py` | 140 个编号、名称和实现入口可校验 | 当前验证证明“入口存在”，不等于 140 个独立行为均被测试 |
| `cli.py` | 自检、能力、资产、工作流和 AI 操作可用 | 缺少统一日志等级、JSON 错误协议、取消命令和运行历史查询 |
| `platform.py` | 提供模块组合和默认动作注册 | 需要项目模板、生命周期容器和统一运行上下文 |
| `models.py` / `errors.py` | 稳定类型和异常分层可用 | COM 错误仍需补充 HRESULT、设备、步骤和恢复建议字段 |

## 真实项目必须补齐的 P0 能力

1. 建立 CANape 17/18/19、不同补丁版本和 32/64 位组合的兼容矩阵。
2. 在真实 XCP on CAN、XCP on Ethernet、CCP 和多 ECU 项目验证连接生命周期。
3. 验证指定 CNA 加载、项目切换、异常退出和 vMDM 资源恢复。
4. 对标量、枚举、曲线、MAP、轴、ASCII 和块标定做真实 A2L 回读/写入/回滚验收。
5. 建立点火、电压、车速、档位、充电状态和台架急停等写入前置条件模板。
6. 为刷写增加文件签名/校验和、供电条件、Boot 状态、断点恢复和失败救援流程。
7. 为诊断增加 NRC 分类、会话/安全访问状态机、P2/P2* 超时和 Tester Present 管理。
8. 将审批接入可信身份，至少支持操作者与审批者分离、双人审批和不可抵赖审计。
9. 所有高风险动作补充硬件在环故障注入：掉线、超时、断电、总线拥塞和回读不一致。
10. 将 140 个能力契约升级为 140 个独立验收用例，并保留真实项目证据编号。

## 发布判定

发布开发基线前至少应满足：

- Ruff、完整 Pytest、`compileall`、`pip check` 和隔离 wheel 安装全部通过；
- CLI、MCP 工具发现、能力注册表、示例工作流 Dry-run 可执行；
- README 不含旧仓库链接或旧产品名；
- CANape 实机冒烟只执行只读动作，不自动终止其他工程师的全局进程；
- 发布说明明确区分软件验证、模拟 COM、实机只读、硬件写入和外部适配状态。
